# 接手 Agent 入口

1. 阅读本目录 `README.md`、根目录 `RELEASE.json` 和当前机器外任务表，再读取机器外配置和该作者最新 Word/附件。`CLOSEOUT-STATUS.md` 仅是历史记录。Word 是图号与语义依据，不能按现有 PDF 数量断定完整。
2. 先查本地来源索引和当前目标 hash；跨批次来源不得只依赖绝对路径。检查用户手改和终审记录。任何不匹配都停止覆盖并保留双方。
3. 能力分流依据 `direct-pdf/docs/CAPABILITIES.json`。工具运行通过、PDF 已导出、内部审核通过、用户终审通过必须分开记录。
4. 公共图形走 `direct-pdf/journal_pdf/scene.py` + `graph_layout.py` + `editorial.py`。不要私有手绘三角箭头、绕过 endpoint audit，或只调整单条文字却不重验间距。统计图柱顶文字使用 `charts.py`。
5. 打包路线按当前工作安排集中处理；PS 默认单栏、无 PS 查验包。不能把一种图种的路线套给不同作者；离线任务输入、输出、状态互相隔离。Illustrator/Photoshop 只有一个共享会话，串行使用。
6. 目标文件替换必须精确匹配已记录旧 hash，先备份旧版，再复核新 hash；接受过的稿件不能由未终审候选覆盖。未终审的完整作者仍留在 `0没做完`。
7. 迁移交接副本中的生产证据和作者原稿是私有资料，只在项目授权盘使用，不进入 GitHub。商业字体和授权软件插件不复制；新机器需由用户合法安装并填写外部配置。

8. 流程图开始、结束采用两端半圆的胶囊形终止框（`terminator`，不可用普通小圆角`roundrect`代替），普通处理框采用直角矩形。任务节点优先标记 `role: start/end`；测量分组不得丢失形状语义。实际PDF须核对圆角，形状审计失败不得发布。

9. 双侧或深层树不能套用仅两层向右的tree模板后直接判双栏。先保留真实父子和左右归属，从外侧叶框向内计算子树范围并实测单栏；双侧递归结构用tree_layout:bilateral及明确side字段，children保留递归关系。该求解器按叶到根测量，普通right模板保持原行为；超出树结构或预算时明确报告，不能压平层级或把单向试排当作全部候选。

10. 统计图/曲线图必须保留源图几何和数据关系；禁止从截图、折线形状或估读刻度重绘数据。只有明确提供并绑定原始数值表时才允许重新生成曲线，且必须逐系列核对源数据与输出。Word内图与外部原图数据不一致时，状态标为“待确认来源”，不得选一方推测、不得交付重绘候选；优先直接保留用户指定的原始图形。

11. 首次加工判断先记录 `source_review`（结构、文字需求、数据保护、拓扑及来源证据）和 `text_review`，再选择方法。用 `preflight` 的 `suggest-route` 比较本地原图—Word—成图配对案例；不要求先填方法才检索，也不把扩展名、能够转灰度或能提取原生文字当图种判断。普通框图重绘；独立统计图完整换字并保留数据；UI截图内文字与外加图题/标注分开。复合图逐面板判断，不因某历史复合图曾保留栅格就外推所有统计图只需灰度。历史删字、引线变动及附件/Word冲突不能成为自动取舍规则。建议、机械检查、实际PDF复核和用户验收分别记录；制作前事实不等于制作后通过。
