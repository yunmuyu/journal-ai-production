# 本地期刊图件生产入口

本目录汇总 **2026.11.04-r46-clean-move** 迁移预览版的当前制作路线，汇合前置筛选、作者目录状态管理和直接 PDF 引擎。安装与升级见 [正式版指南](../docs/RELEASE-GUIDE.md)。能力按 `direct-pdf/docs/CAPABILITIES.json` 逐项判断；正式发布不扩大原有支持范围。

导入失败先查[已有能力与失败分流](../docs/production-tool-recovery.md)：direct-pdf 当前入口的格式限制不代表 Office/Visio 兼容工具缺失，先复用已有入口和缓存，不重复实现。

## 接手流程

1. 在仓库外复制 `config.example.json` 并填写交付目录、状态目录、字体配置和缓存目录。禁止把机器配置或字体文件提交仓库。
2. 用 `preflight/` 检查 Word、原包图源和可处理性；记录来源映射、路线、候选与替换备份。常规照片、截图及明确布局的组合位图使用 [公共 raster CLI](raster/README.md) 导出JPG；可编辑重绘由 `direct-pdf/` 公共 scene、layout、font 和 PDF audit 生成/检查PDF。工作台回传通过独立质量门，不能只采信执行者“完成”。
3. 根据Word全部图号与实际PDF/JPG内容完成独立检查，候选回到现有工作台待用户终审。交付目录与命名沿用 [工作空间约定](../docs/workspace-management.md)，不得让候选直接覆盖已批准交付。内部通过不等于用户终审通过。

常规JPG处理不依赖Photoshop，使用 `python -m raster render <plan.json>`。先核对是否有更合适的可编辑或矢量源件；只有位图且不宜可靠重绘的截图、照片或复杂图才按保留内容路线处理灰度、显式裁切和尺寸。不能仅凭PNG后缀选择路线，也不能根据像素字高自动改成重绘、拆图或双栏。宽度来自已核对的任务计划，不把历史“PS默认单栏”当作跳过逐图来源与尺寸判断的理由。Photoshop仅为公共解码器未支持的必要特殊格式保留兼容用途，不制作PS查验包。相同处理动作按类集中执行，输出仍按作者归位；独立离线任务可以并行，共享Adobe会话和同一目标文件必须串行隔离。正式文件替换前校验当前hash，旧稿留在回退归档，作者原件始终保留。

## 已固化的公共约束

- 直接 PDF 流程、复用现有筛选/字体/布局/交付保护工具；不要在作者脚本另写测字、箭头或字体子集算法。
- 流程图开始、结束节点使用两端半圆的胶囊形终止框（`terminator`，半径为短边的一半），普通处理节点保持直角矩形。`graph`、测量分组及显式 `scene` 节点统一处理；标签为“开始/结束”（或 Start/End）自动识别，其他终止节点用 `role: start/end` 明确声明。输出前检查终止节点形状，不能只核对文字及箭头。
- 流程图普通连接采用公共四节点头箭头布局，基础长度 3 mm 且端点贴框；文字框以真实墨迹计算，8 pt 参考留白左右 4.5 pt、上下 2.7 pt。
- 可编辑重绘版面先紧凑重排，正文允许6–8 pt；低于6 pt要重新排布，上下角标按语义核对。该门槛不套到图片内部文字。输出描边可见线宽目标0.5 pt；数学变量斜体、数字正体。
- 常规柱图顶端数值标签测量实际墨迹并维持同一间距；发生碰撞时重排图表，不用高低错落掩盖冲突。
- 内部来源/内容/版式复核与用户终审是两个状态。未经作者终审，状态不能写作通过。

## 实测范围与限制

本地 Windows 上已有真实图件生产记录；当前验收范围见 [r32 发布说明](../release-notes/2026.10.20-r32-production-baseline.md)。[旧收尾记录](CLOSEOUT-STATUS.md) 保留为历史问题证据，不能代替当前任务状态。私有证据和作者图件保存在授权私有位置。代码可运行不代表跨机运行或 Adobe/PS 自动链路已验收。PS 自动制作、任意转曲 SVG 文字重建、复杂多面板、复杂嵌套 Form 描边归一、用户字体/Adobe 插件在新机器上仍需分别验证。

开始具体任务先看 [AGENTS.md](AGENTS.md)、当前本地任务表、[直接 PDF 使用说明](direct-pdf/README.md)与[能力表](direct-pdf/docs/CAPABILITIES.json)。历史工作台及 Illustrator/Photoshop 脚本保留为兼容路线；普通新任务不要求先走工作台同步或制作前逐图确认。

## 任务质量门禁

对子代理批量任务需要保存输入、产物和独立复核证据时，使用[质量优先任务协议](task-quality-workflow.md)和[四阶段 CLI](task_quality/README.md)。它复用现有来源哈希和交付保护，不能替代源图核对、视觉复核或用户终审。

树状图使用 `kind: tree`，显式设置 `tree_layout: bilateral` 启用左右递归布局；旧默认right模板保持原行为。根分支必须按原图标明 `side: left/right`，children可递归嵌套，不能压平层级。算法从最外侧文字框向内回算子树占高与列宽，再布置父节点及无箭头汇总线；同侧同深度等宽。可用root_vertical保留根节点竖排、节点wrap_chars指定纯中文换行（1—20，不拆英文词）。仍以80mm单栏、6pt下限及实际PDF审计为准，超限明确返回重新排布要求，不自动改双栏。最多80节点、12层，不支持有向环或任意交叉连线。
