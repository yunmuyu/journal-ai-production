# 提前实测当前方案的栏宽容量

准备好来源绑定、语义和布局规格后，可先运行内部只读检查，再决定是否进入完整PDF制作：

```text
node workbench/run-public-pdf.mjs <已配置Python> capacity <当前规格.json> --profile <字体配置.json> --source-root <素材根目录> --cache <字体缓存目录>
```

这是统一入口可复用的内部组件，不是其他生产或回传入口。检查直接复用 `compile_figure` 的字体测量、布局、紧凑树/精确箭头重排、整图缩放和几何审计，包含生产2pt留白及原有描边预留。不会先渲染PDF、不会另试8/7/6三档、不会改规格或工作台决定；字体缓存仍可按现有配置写入。来源哈希不一致时拒绝检查。

输出 `capacity.summary` 是可读结论，`figure_id`、输入规范化JSON的 `spec_hash`、实测时绑定的 `source_bindings` 用于匹配当前图件与版本。源码变化后必须重测，不能将旧报告挪用到其他规格或来源。它们不代替工作台当前 `reviewVersion` 和人工决定的核对。

- `layout-checked` 只表示当前方案的可编辑文字字号与布局几何检查通过。没有实际PDF、源图语义或视觉检查，不表示可出版。
- 字号低于6pt仍返回原 `layout_reflow_required`。例如309pt宽的8pt方案，在80mm及双侧2pt留白后约为5.75pt，必须重新布局。
- 字号通过但箭头末段、框间距等几何失败，仍返回原 `no_feasible_layout` 和实际检查值；不会因为字放得下就忽略箭头。
- `minimum_width_mm_for_font_rule` 仅是当前固定布局满足6pt字号约束的宽度下界。箭头、内容保护和其他几何约束可能需要更多空间；另一个布局可能更紧凑。这不是完整图件可实现的最小宽度，也不是“单栏永远放不下”的证明。
- 位图内部文字及源路径中的未登记文字不按像素字高估算字号。报告明确注明此边界，仍须独立核对内容和可辨识性。
- `single`、`double`、`auto` 沿用现有规格含义。明确双栏的方案直接检查双栏，不强制补一遍单栏审批；`auto` 仍不会自动改双栏。人工栏宽、拆分和保留原布局的要求须由调用方按当前图件版本保留；报告只提供证据，不写回决定。

完整渲染遇到相同容量失败时也携带相同 `capacity` 证据。现有工作台诊断适配器会保留其 `summary` 和计算值，原始失败码与原始几何问题保持可用。
