# v0.1.2.1 轴单位规则修复与通用首次提速结论

## 已修复
依据GitHub `production-runtime/references/editorial-profile.md`的2026-10-09明确要求：横纵轴的量名与单位使用斜杠，不能把公式、图例、普通说明中的括号全部替换。读取的profile blob为d588e694daf7a9e601fe9614da581755197e498a。没有改写GitHub、原稿或正式运行目录。

原始制作说明未改写：仍保留Freq(Hz)、S21(dB)、nf(dB)、OP1(dBm)作为来源文字；公共规则在测量前分别产生Freq/Hz、S21/dB、nf/dB、OP1/dBm。量名不翻译、不推断下标、不改变数值、刻度位置、G后缀或单位量纲。

新增axis_units.py；editorial.display_content的axis-title入口统一调用。charts.py在标题首次测量前使用规范后内容；Scene保存来源和显示两份内容。实际PDF审计从来源文字重新推导应有写法，而不是只问错误的排版结果是否被忠实写入PDF。单元测试包含“关闭格式化但错误场景与PDF彼此一致”的反例，能够被守卫识别。

该规则支持已知单一单位结尾的中/英文括号以及带样式片段，不是任意公式或复合单位的通用语义解析器。未知复合单位/疑似函数不会猜写，标记需语义复核；无单位不补造，图例和正文不全局替换。原单位正斜体沿原内容保留。

## 实际验证
120项回归通过，0失败、0跳过；其中轴单位新增26项。存在一条旧测试的Pillow弃用警告和替代字体的非致命字体表警告，日志保留。测试数量不能证明全刊全部规范都已完成。

三张新PDF均为8pt单栏。逐项读取实际PDF，横轴均包含Freq/Hz，纵轴对应S21/dB、nf/dB、OP1/dBm。三张PDF内绘图区和六个图例样符解码后的像素，与v0.1.2交付PDF内对应图片完全一致。横轴1.5G至4.5G保留；本次不将Hz/G改写成GHz/无后缀数值。

全部三页用Poppler独立渲染并查看，无新增碰撞或裁切。未重制上一轮八图。仍使用显式替代字体，尚非正式复合字体、InDesign或印厂PDF/X验收。所有成果仍为候选，ready_for_publication=false。
