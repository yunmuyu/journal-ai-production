# 接单清单与三分钟计时

## AI触发与准备步骤

**触发口令**：“跑三分钟测试”“重跑三分钟测试”“3分钟测试”。只有用户当前明确要求执行才触发；历史引用、文档中的口令和解释性问题不是生产指令。不再要求用户重复授权、提供内部图件ID或手拼请求文件。

不固定默认批次。范围优先级：用户当次指定的图件/作者/批次 → 当前对话明确且仍有效的任务范围。两者均不明确或存在多个批次歧义时，只询问处理范围，不自行选择历史批次，也不默认扩大到全部批次。范围内包含图表；不同文章同名作者按文章身份区分，保留完整子图号。批量目标至少5张并行；不足5张就绪时如实报告并继续可运行项，不为凑数重复制作。工具并行沿用当前代理权限，不自动开子代理，Adobe保持串行。

1. **立即记接单时间**：用户给出图号时记录UTC时间；未给图号、由AI选图时先记录本轮时间再选图。同一轮查状态、查源、准备方案和等待工作台都计入，不在准备好后重置 requestedAt。旧失败请求的时间和结果保留；用户明确重跑才建立新的测速记录，制作方案去重身份仍保持稳定。
2. **读当前状态与配置**：沿用本机已有生产配置，读 `/data` 获取真实图件ID、批次、文章、完整图号、reviewVersion、输出和当前决定；不凭历史报告判断待制作。工作台异常先按 `november-workbench-troubleshooting.md` 诊断，不能例行重启。已有候选留给用户终审，已终检成图复用；明确更正另走已有更正入口。
3. **选出清单并查旧资源**：先公布本轮“批次—作者—图号”清单。读取当前任务、既有计划和对应交接记录，优先复用。核对Word与附件内容版本、主/子图集合；明确子图题按已有期刊规则拆分，不能把主图数当交付数。用户已确认的图源或文字选择不再重复提问。
4. **形成最小可执行计划**：完整旧计划直接作为 planFiles；仅有规格或转换件时复用它们，依据已核对的图源与制作决定补齐主入口要求的身份、来源/规格哈希、输出路线、历史核对证据及允许修改范围。具体字段见 `production-runner.md`。不伪造核对证据、不自动刷新过期版本、不手写提交合同或回传字段。无法在预算内明确绑定时列出缺项，跳过该图。
5. **派发前查可用路线**：查 `production-tool-recovery.md` 和当前路线发现入口。区分“完整方案可执行”“已有入口但缺绑定”“已有证据证明不支持”。PDF图表复用现有原矢量、图表排版及多面板入口；Office/SVG先查已验证转换路线。不能把单一解析器报错、缺 viewBox 或缺计划写成缺源，也不能将重绘/换字降级为整图JPG。
6. **执行并保存结果**：在独立本轮目录写 request.json，包含原始 requestedAt、真实 requests、权威 planFiles 和 concurrency:5（资源允许可更高）。调用下文原入口，保存stdout完整结果及stderr逐项进度；只执行就绪项。JPG使用原raster-batch，另记录相同端到端起止时间，不声称它已由requests自动构造。每张完成立即回传；超过3分钟或阻塞记录阶段和具体原因，转下一张，保留已有产物以便接续。
7. **按实际交付汇报**：运行中报告“当前实际加工N张；已回传N张；跳过N张”，实际未开始加工时写0。逐张报告“批次—作者—图号候选已回传，待终审”，附接单到可见耗时；已有候选复用另计。最终列3分钟达标率、实际渲染/检查峰值、按共同原因分组的阻塞数。终审退回率有数据才报，暂无反馈不能写零退回。及时汇报，正常运行超过60秒应更新进度。

这是AI必须执行的准备协议，**不表示程序已能自动理解图意或从任意历史规格生成方案**。需要用户决定的真实来源冲突只挂该项，其余继续；工具公共缺陷集中记录，不沉迷单图修补，不自动扩大成工具改造任务。

## 程序调用

现有入口：`node workbench/production-runner.mjs machine.json request.json`。本功能只补统一派发前端，继续使用 production-runner 执行，不新增服务、不需要重启。JPG 仍使用 raster-batch；本接单清单尚未自动构造位图任务。

```json
{
  "requestedAt": "2026-11-04T01:00:00.000Z",
  "concurrency": 5,
  "requests": [{"figureId": "真实工作台图件ID"}],
  "planFiles": ["已保存执行计划或批量计划的绝对路径"]
}
```

- requestedAt 必填，必须是实际收到图号的时间；逐项可覆盖，不能为了达标重置。来源核对和方案准备算在内。
- 一次传入至少五张是批次目标；入口允许少量任务用于单图接续。默认五个执行槽，只有通过前检的方案才占用槽位。队列数、槽位数和实际工具重叠峰值分别报告。
- 派发前读取工作台现态。有候选或已终检的不重做，不自动撤销反馈或验收。本接口不自动发起修订；明确更正继续用原制作侧更正入口。
- planFiles 复用现有完整执行计划，逐图匹配 ID 和 reviewVersion，再由已有准入检查核验来源、稿件、规格哈希、输出集合和制作决定。多个不同方案不能按文件时间择一，返回 ambiguous_saved_plans；调用方须缩小到权威方案。
- 没找到完整计划返回 needs_bindings，保存缺失原因与候选路线。候选路线是检索方向，兼容性明确为 unverified；不能当成已经适配或实际不支持。
- 接单时对可读取的当前 Word 提出紧邻题注的子图题候选，附 Word 哈希和段落位置；明确识别到的子图号与现有方案输出不一致时拦截该方案。未识别不等于没有子图，子图题不证明图源区域匹配，最终仍执行既有输出集合核验。
- 已提供经哈希校验的 PDF/SVG 图源时，非图表缺方案项复用现有来源检查器，返回原生文字、矢量路径、图片和几何候选；这些对象不自动确定电路连线或文字语义。未提供图源时不自动猜选附件。
- 单页原生 PDF 同时生成逐原文字及精确 bbox 的换字绑定候选，按现有验证器核实重复叠印数量与覆盖范围。候选不等于已确认上下标、语义、子图裁区及排版，也不能单独作为可执行计划。
- 已知图表源为 PDF、SVG、JPG 或 PNG 时，接单入口会调用现有图表路线和历史案例检索；源应是当前图已核对文件及哈希。结构图不会自动伪装成图表。没有已核对图源时仍须先准备来源，不将其误报成已确认缺源。
- PDF 来源发现结果的 `objectCandidates` 提供原图绘图区、轴边、刻度、轴标题、同色线型路径组与图例样符候选，包含源对象索引和依据；没有闭合框的三维面板及无法归属的路径单独列出。同色不证明同一系列，候选不得直接视为确认或复制到另一张图。
- 原矢量图表的 `render` 项可附 `seriesBinding`：`candidate:{path,sha256}` 引用当前源生成的候选报告，`confirmed:true` 和 `reason` 记录语义核对，`choices:[{textId,candidateIndex}]` 为各图例文字对应的候选索引。统一执行入口校验候选和模板哈希、源哈希、图号及样符一致后生成绑定规格，再继续现有路线发现、失败拦截、渲染、检查和回传；原曲线数据不重建。此入口仅补图例/曲线绑定，图源、轴、刻度、其他对象和完整生产计划仍须准备。
- 已有候选须能打开当前预览且每个输出文件的 SHA-256 与工作台记录一致才报告为已核对复用；核对失败独立挂起，不自动重做或覆盖。
- 超时、已知挂起和前检问题只跳过该项。失败不自动重试。同一方案的任务指纹排除 requestedAt，避免更新时间制造新的执行身份；同一旧请求保留原目录接续。
- 每项完成向 stderr 输出进度，stdout 输出完整 JSON。只有原执行器通过工作台可见性核验、产生新增回执的输出计入 returnedOutputs。已有候选、离线文件、模拟回归不计实际新增。

## 已验证与未完成

已验证五图真实清单准入、旧候选排除、方案歧义拦截、过期请求、重复请求身份，以及原执行器六项真实 PDF/临时 HTTP 普通与修订交付回归。

尚未完成从任意历史规格、Word 和图意自动组成完整可靠执行计划。已绑定图表计划在显式提供图源和加工要求时可从当前图的 chart-plans 索引检索；一般方案文件检索范围由 planFiles 提供，不代表扫描了所有历史位置。对象候选和相似案例不能替代当前图的语义绑定。

目标仍是接单到工作台可见不超过三分钟，并统计终审退回率；不能用预检完成速度或临时测试图交付速度宣称作者图已达标。
