# 内部工作空间与用户交付使用说明

本约定由用户于 2026-11-02 明确指定。后续接收压缩包、制作、修订、整理和交付时直接执行，不要求用户重复说明。真实路径从仓库外的项目配置或本期交付约定读取；本文不保存作者材料或机器路径。

## 用户和 AI 各自使用什么

- 本期“作图”目录是 AI 负责维护的内部制作空间，保留名称“作图”。用户不需要进入、理解或整理内部文件。
- 用户通过现有工作台查看图件、批注和验收。保持现有界面、地址、批注、截图和链接可用。
- 同级交付目录使用用户已经指定的实际名称。例如本期为“十一月图件”；“月份”只是说明中的变量，禁止据此另建名为“月份图件”的目录。
- 用户授权 AI 自行安排内部目录与例行维护；不等于授权丢弃原稿、批注或验收记录。

## 内部目标结构

| 目录 | 用途 |
|---|---|
| 原稿 | 原始 ZIP/RAR、Word、图源，保留原样 |
| 制作 | 按批次、作者保存可编辑源文件、制作规格 |
| 待终检 | 当前修订稿及对应检查结果 |
| 工作台 | 页面、预览、批注、截图、验收数据 |
| 历史 | 被替换的版本及必要回退资料 |

这是逐步归并的目标，不代表旧项目已经迁移完成。先读取当前绑定关系再改目录，不为形式统一强行搬动被占用文件，不关闭用户软件。兼容联接记录实际目标，避免形成多套状态。

## 收到原始作图压缩包

按 [交付目录说明](delivery-folders.md) 调用 `scripts/new-delivery-folders.ps1`：

```text
<用户已指定的交付根目录，例如：十一月图件>/
└─ 月份-编辑姓名-篇数/
   ├─ 原始压缩包.zip 或 .rar
   ├─ 作者甲/
   └─ 作者乙/
```

保留用户明确指定的批次名。核对压缩包内文章与作者，不能只根据包名猜名单。同作者多篇按标题分隔。仅要求建目录时，原始包必须复制并校验，作者目录留空；由用户指定的其他 AI 填图。获授权交付图件时只放规范命名的 `作者-图号.pdf` 或 `.jpg`，不混入脚本、日志、候选稿和报告。

## 版本与批注

接手先读取当前项目的绑定记录，沿用现有交付根目录、工作台和权威台账。本文不是初始化指令，不要求每个 agent 重新搭目录、重写台账或取消旧结构。内部结构是可逐步调整的目标，不是强制迁移模板。存在同类目录时先核对用途及文件，不能创建另一套当前状态。

## 旧稿复用与阻塞范围

源件哈希相同只证明来源字节一致，不证明成图已经合格或已经验收。未在某一 publications 目录查到记录，只能记为该处未找到；先检查现有工作台、正式验收记录和交接证据，不能据此断言从未验收，也不默认要求用户回忆。

旧检查脚本的 FAIL 是待分析结果，不自动等于重做。确认检查工具及适用规则，再核对实际 PDF、原图、正文与上下角标、位图用途和实际字号。照片含位图不等于错误；不得把最小上下角标字号当作正文。真正缺陷按影响选择复用、小修或重做，不把所有历史图套用同一结论。保留原始检查结果并标明未复核范围。

先用当前 Word、图源和已有规则解决图号、中文编号、图题与表题差异；不得自造缺失图或静默改号。仍有影响内容的真实歧义时，只询问受影响项目，同时继续其余已授权工作。整批最终批准不构成制作、复核或普通修订的开工审批。

遇到工具运行失败，记录实际命令、环境和错误，只对已验证范围下结论。单次执行策略或程序集错误不代表整台电脑都不能使用该工具；不得据此另写私人替代生产引擎。

每个图号/分图号只有一个当前输出映射；旧版退出当前目录，集中留存。制作使用现有 GitHub 公共工具，不另建私人替代生成路线。通用工具留在工具库，本期材料留在内部空间。

常规照片、截图与明确布局的组合JPG使用公共 `portable-production/raster`，不依赖Photoshop；原包来源和处理路线先核对，可编辑重绘使用PDF工具。Photoshop仅为必要特殊格式保留兼容入口。图片内部不推算字号或机械触发重绘/拆图/双栏，但内容完整、关键文字可辨及灰度信息保留仍须独立核验。执行Agent共用工具和质量契约，派单与回传的技术检查不转交用户重复审核。

批注绑定被批注的版本。修订后保留原批注、截图和修改说明，更新当前图与预览；不能把旧版验收套用到新版。目录迁移前保存绑定清单，迁移后核对文件哈希、预览、Word 链接、反馈和验收版本。不得用新建空工作台代替旧工作台。

## 通过与交付

工作台收包现可接入 [上传作图包](workbench-archive-intake.md)：登记后显示作者与文章，相同原包按哈希去重；已经在其他现有工作台制作的文章按完整 Word 路径关联并保留原图件入口。上传登记不自动开始整批制作，不重置已有进度，不记录整批批准。接手时先读运行时配置与登记表，不能因为空图列表就把文章判为通过。

当前由 Codex 直接调用公共工具完成核对、制作、自检和回传，暂停 WorkBuddy 派单及自主恢复；详见 [执行器接入与可移交目标](workbuddy-executor.md)。保留原任务、来源核对结果、批注和历史候选，不新增重复执行器。长期目标为兼容执行 Agent、GitHub 工具、资源与用户少量关键决策。先稳定现有链路，不因此另建平台。按图种/处理方式逐图排队，不按篇连续制作。执行会话主动领取；当前未配置外部唤醒接口，不能把排队或重试显示为 AI 已开工。来源阻塞须显示具体问题并保留补齐重试入口。

同名稿件的工作台短标签使用“姓名＋固定序号＋标题前两字”；同组标题都以“基于”开头时略过这两个字再取。用户指定标签优先，`displaySequence/displayLabel` 保存在原包登记记录中，不随排序或重启重新编号。短标签只是显示元数据，身份仍为稿件 ID；不改原稿署名、完整标题、图件/批注/验收绑定、Word 链接和交付命名。同名不证明同一人，标签冲突不得合并稿件。

逐图验收和整批最终批准是两层状态。即使逐图都勾选、自动验收或文件齐备，也不能推断整批已通过。

**只有用户明确说“这个全过了”或同等明确的整批确认，才记录该批次最终批准。** 记录确认所针对的批次和版本；确认后又修改的图需要重新验收。不得把此文档本身当作批准。

历史记录、临时文件在验证和回退需要满足后再清理；不得删除唯一原稿、当前稿、用户反馈或必要制作源文件。对外只说明实际完成的状态，不把目录快照、机械检查或候选稿写成最终验收通过。
