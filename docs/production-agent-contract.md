# 生产执行与交付协议

先读取当前任务的原包、Word、原反馈、已完成输出和冻结版本；不要重新猜选源或用旧技能副本替代现行引擎。

## 执行入口

直接 PDF 统一执行 `node workbench/run-public-pdf.mjs <配置中的Python绝对路径> <journal_pdf参数>`。
入口固定当前仓库的模块路径、UTF-8，并输出实际加载模块路径；字体方案仍由任务显式传入。
禁止自行使用 `runtime/current/engine` 或系统 Python。JPG沿用公共 raster；要求换字或重绘的图不能降为灰度JPG。

### 已有来源准备能力

- Office元文件：`lib/convert.mjs::convertOffice` → `scripts/convert-office.js` 已有EMF/WMF→PowerPoint→PDF的实跑结果。赵鹏与田腴已有实例；不能因PDF解析器不收EMF而报缺源。
- 保留矢量的PDF灰度派生：`scripts/prepare_pdf_vector_gray.py SOURCE.pdf OUTPUT.pdf SOURCE_SHA256`，使用配置Python；目标必须新文件。RGB图像或未验证颜色操作会明确拒绝，不能自行栅格化绕过。
- 完整矢量图体：`source_vector_body`保留原路径并显式绑定源字；并不要求Agent重建每个电路符号与拓扑。重复源span只在全部属性完全相同时共用一个绑定；读取实际文字列表去重，不能删除异文。
- 混合图片与矢量图不能强塞纯矢量入口；`source_mixed_body`仍可能报资源清理缺陷，保留具体证据，不冒充已支持全部来源。
- 已确认照片/截图保留路线使用`raster-batch`的`autoPlan:{crop:null,quality:95}`，见raster-preparation.md。它不自动选择保留路线，不会把应换字图降级。

判断“工具不支持”前须查上述入口和对应已有证据；参数错误可以明确修正时继续，不按固定失败次数挂起。只有语义疑点或已确认能力缺陷才停止该图。

## 接续与回传

- 公共 PDF 的完整执行入口为 `node workbench/production-runner.mjs <machine-config.json> <plan.json>`，或导入 `runProduction` / `runProductionBatch`。Agent只提交来源与加工方案；封装、实际宽度、任务分流、契约和HTTP回执由入口完成。调用规格见 `docs/production-runner.md`。
- 每个执行单元独占图件及输出目录；只接有明确主图号、完整输出集合和来源决策的任务。
- 普通新图和修订由公共执行入口分别调用现有 prepare-import/submit-imported-pdf 与 prepare-candidate/import-candidate；内部共用 pdf-candidate.mjs。不得让作者代理手写这些中间文件或回传流程。
- 普通新图的来源清单和派生来源副本放在工作台来源空间内；复制后核同SHA。保留父Word/压缩包身份。
- 主线程是唯一工作台写入者。代理完成阶段只算 prepared；主线程核对当前输出SHA、待终检状态及HTTP可打开后才算 returned。
- 任务参数错误（路径根、缺SHA、上下文类型）不计作工具能力失败；修正参数后继续。同一工具能力阻断集中记录，其他代理不得重复撞相同错误。
- 主线程按production-admission.md登记已知故障、核对实时就绪队列后派发；代理交付的JSON必须通过入口结构检查，不能以JSON可解析冒充接口有效。render是数组，每项spec为path/SHA引用；预检失败日志必须交主线程登记到对应specSHA。
- 当前PDF并发额度6，工具并发按就绪任务和资源调整；Adobe仍为1。不因工具额度增加而同倍增加代理，转换/封装/检查/回传仍由确定性工具承担。
- 源文件存在但解析器不支持，不等于缺源；先复用既有Office转换和历史案例。内容冲突单图挂起。
- 无法继续需留下精确失败命令、错误码、耗时、源/说明/报告路径。只准备材料不能报完成，不能把拟定检查写成已通过。
- 用户暂停后不得继续生成、提交或开启代理；已启动Office/Adobe现场不强杀、不盲删锁。

## 度量

以成功回传事件计产量：按批次/稿件ID/完整输出图号/SHA去重；同时记录退回和重做。代理数量、转换件和离线候选不计入每小时交付量。
先跑通一张从来源到工作台的完整路径，再给同路线扩并发；没有经过完整链路验证的路线不批量派发。

## 公式来源与负号规则

含公式图件先核对作者源中是否保留 MathType/OLE 对象；保留时优先复用，不把普通公式位图或可编辑 PDF 文字宣称为 MathType。

已确认编辑规则：一元负号使用 ASCII `-`（U+002D），包括负数、负方向、`-j` 和负指数；二元减法使用 `−`（U+2212）。公共 `editorial.display_content` 在测字和生成前调用 `mathematical_signs`，对分段公式合并判定后保留原分段样式。公式角色明确为 `formula`/`math`；普通标签不把型号、日期和单词中的短横当成减法；`code`/`command`/`path`/`literal` 原样保留。该规则不是整图替换所有横线。

## 树形图框距与组间距

2026-11-03用户最新决定：树形图统一固定组内框线外缘净距3 pt、不同组框线外缘净距6 pt，以8 pt设计字号为基准；整图缩放时同比缩放。该决定取代旧的2.5/5 pt方案；单向树与双侧树一致，不提供两套选项。

按子框和子树测量、排布后，推导父节点及连线。工具直接按固定3/6 pt生成；旧规格显式要求2.5/5 pt必须拒绝并重新排版，不能静默沿用旧值。保留图稿及其终审历史；本次不主动重新加工旧候选。

## 无图例图表路线

图表仍须先按源件与语义选择路线。已确认原图无图例时，规格 `legend_review` 必须记录 `present:false`、当前选中源件SHA及具体核对理由；不生成图例，不添加图例遮罩。图中有图例时仍须逐项绑定系列、样符及文字。不得以空列表推定源图无图例。

- 已核对的朝内刻线位图走图表入口，必须保留绘图区像素；无图例不创建清除区域。
- 已识别的Matplotlib SVG绑定全部原曲线系列，核对转换前后几何摘要；无图例也不得忽略系列。
- Office来源的矢量PDF如不能安全套常规viewport，允许在图表加工证据中使用已验证的source-vector-body完整图形保留换字：绑定图源SHA、明确无图例、刻度和轴题目标、全部源文字替换和原路径多重集保真。此能力不代表任意PDF图表都能自动识别或换字。

相关代码 `journal_pdf/charts.py`、`journal_pdf/agent_spec.py`、`workbench/processing-evidence.mjs`；图表语义与无图例判断仍须与原稿核对，不自动标为终审通过。

### 保留原矢量的无图例图表

使用公共 chart-redraw 场景路线，必须绑定源 PDF 坐标轴和刻线及人工确认无图例；布局时测量实际字形和轴线墨迹，使用 8 pt 并自动安排刻度、轴题间距和对齐；实际 PDF 审核与来源路径核验均须通过。不得重建曲线或更改数据。当前不覆盖有图例、额外图内标注或无法绑定源刻线的复杂图，不得将其作为此路线已通过。

## 多媒体子图入口（2026-11-03）

- `grouping: word-inline-columns` 用于当前 Word 连续行内网格且末尾有明确逐列子图题的情况。逐输出 `members` 必须与路线的 `selected`、`additionalSelected` 一一同序，独立绑定 Word 媒体哈希和实际来源哈希；浮动图片、缺行、换序、重复来源、标记不明不自动放行。
- 如来源为原包单页单图 PDF，`originPdf` 绑定 PDF 哈希，独立核验无其他绘图/文字/蒙版、图片覆盖页面，且提供的图片字节与 PDF 提取件完全一致。用户终审仍由用户执行。
- 公共 raster `column-fit` 按最窄源的像素宽度等比缩小其他输入后连续竖排，不上采样、不改变内容顺序。现行 raster 报告的 `resampled` 只表示最终 target_dpi 整图重采样；column-fit 的输入缩小应根据各输入像素宽与 placement 记录判断，不应将 `resampled:false` 解释为各输入均未缩放。
- 实际回执：孙晨旭图5.1、5.2已回传，采用两个子图各四张原 PDF 的无损图像提取件。该案例允许行列结构可核实，不代表任意复合图均能自动归属。
