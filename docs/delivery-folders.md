# 收到作图压缩包时建立交付目录

用户发送“某月、某编辑、多少篇”的原始压缩包时，先建立外部交付目录：

`月份-编辑姓名-篇数/原始压缩包 + 作者姓名文件夹`

运行 `scripts/new-delivery-folders.ps1 -Archive <原始ZIP或RAR> -Destination <交付根目录> -Month <月> -Editor <编辑> -Count <文章数>`。

`Destination` 必须使用当前项目已确认的实际交付目录（例如“十一月图件”），不得把文档中的月份变量当成字面目录名“月份图件”。先检查已有批次，重复接手不另建一套；本工具只负责目录和压缩包，不启动制图或变更验收。

- 原始压缩包原样复制，校验 SHA256；作者目录留空，不自动制作或复制图稿。
- ZIP 兼容中文 GBK 文件名及 ZIP 自带的 UTF-8 标志；RAR 使用 WinRAR UnRAR 列表读取，不解压执行内容。
- 从 Word 文件名核对篇数与作者。命名无法识别时停止，核对后可传入 `-Authors` 名单，不能猜测。
- 同一作者多篇时，以文章标题再分子目录，避免图1等同名文件覆盖。
- 重复运行不覆盖压缩包、不清空已有图件；同名不同内容压缩包报错。
- 月份优先采用用户明确指定值，不能擅自纠正既有批次名。
- 外部交付目录与内部工作台分开。不得改变批注、链接、逐图验收；只有用户明确说整批全过，才记录整批最终批准。

工作台上传入口见 [workbench-archive-intake.md](workbench-archive-intake.md)。脚本新增可选 `-ManifestPath` 输出机器可读来源回执，`-SourceRoot` 仅提取已核验的 Word 到内部原稿目录；不指定时保持仅建交付目录的用法。共享检查位于 `scripts/archive-manuscripts.ps1`，重复运行核对已有 Word 哈希，不覆盖不同内容。
