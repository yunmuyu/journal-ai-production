# 制作保真检查补丁（待发布）

基于 r47 / `87ba08a` 的局部补丁。复用现有制作、工作台回传和交付清单，不替换正式引擎配置、不重做历史图件、不改变用户验收。通过代码测试不等于已安装、已上线或 InDesign 置入通过。

## 制作与交付检查单

新 PDF 回传沿用 `verifyProcessingEvidence`，在原有来源/报告/产物哈希核验后，附加统一检查单：

- 正式字体配置指纹、各字库哈希、实际 PDF 字体/字号/样式及嵌入证据。
- 实际灰度、页面尺寸与本图计划宽度、可编辑正文基准 6–8 pt、可见描边 0.5 pt、文字集合、纯黑文字及与制作说明绑定的四边目标留白（默认0.25pt，可显式覆盖）。
- 未检查值明确为 pending，错误为 failed，不能用 `overall_checks_passed` 替代具体证据。
- 检查范围如实保留：位图中的字号不按像素估算，位图线条/填充轮廓不宣称已经归一为 0.5 pt。来源内容、连接语义、实际尺寸视觉和 InDesign 置入仍待复核。
- 离线候选、工作台可下载预览的候选、用户已验收分别记录。只有现有 `verifyProductionDelivery` 验证当前版本后才记录已回传；既有收据不自动授予用户验收。

r48曾针对至少2pt旧下限加入600dpi测量像素保护。r49按新默认规则改为1200dpi测量和四边目标值±0.065pt合同，默认0.25pt，显式0～12pt可控。位图插值偏差从未改原件有限次逐边校正，不放宽容差；原图内容不缩放，重新打开后验证原视口。详见r49-pdf-padding-candidate.md；这不改变历史r48验证记录。

## 作者打包按情况使用

不自动打包，不改变普通制作流程。需要时从已有 `collaboration/current-delivery.mjs` 生成的当前交付清单创建新 ZIP：

```
node journal.mjs package --config <外置机器配置.json> --request <打包请求.json>
```

请求字段为 `manifestPath`（当前目录 manifest.json）、`articleId`（明确稿件 ID）、`output`（新的 .zip 路径），可选 `numbers` 指定本次图号数组。未指定 numbers 只收该稿件在当前清单中的全部图，不冒称已核齐 Word 全部图号。

- 作者身份未明确、重复/缺失图号、来源哈希变化或清单存在未解决问题时阻断。
- 只读当前交付文件，不按文件修改日期猜新版，不混入旧稿；输出必须新建，不能覆盖现有 ZIP。
- ZIP 内按“待终检”和“排版定稿”保留状态，并附不含机器路径的交付清单。打包不改变工作台、台账或验收。
- 该命令只封装已有版本，不触发制作或自动发送。`produce` 不会调用它。

## 上线边界

本补丁须在最终测试后建立新的候选版本清单。旧 r47 的发布清单和生产机器的冻结签名不能被就地改写成新版本已验收；上线和正式发行需独立授权。测试使用的作者原稿、字体、机器路径和私有证据均不进入 Git。

## 提前核对栏宽容量

```
node journal.mjs capacity --config <外置机器配置.json> --spec <本图制作说明.json> --source-root <已绑定来源目录>
```

复用制作时相同的布局、字体、几何检查，不生成 PDF，也不改台账。返回当前图 ID、制作说明哈希、已核对源件哈希、实际栏宽/缩放/字号和可读的冲突原因。容量不够时保留原有错误码，并说明当前版面缩后是否低于 6 pt；不把一种试排失败说成所有方案都无法单栏，不自动改用户选定的单/双栏。普通制作报错也携带同样的信息，无需另走一个制作器。
