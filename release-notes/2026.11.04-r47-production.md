# 2026.11.04-r47-production

本版将当前公共生产工具与 main 合并，修复迁移预览版遗留的 12 项失败，并接通唯一入口 `node journal.mjs`。这是代码和资料恢复的发布，不代表所有待制作图件已经具备语义绑定。

## 已收口

- 列布局由父级统一管理标题，消除重复标题导致的顶端错位和额外留白；生成时统一 3 pt 框距、6 pt 组距及真实箭头端口。
- 保留 main 的源对象覆盖、实际 PDF 可见性、数字格式和字体检查，并接回当前图表、多面板、灰度与联动排版能力。
- PDF 最终留白归一化后重新记录真实页面尺寸，避免加工通过而回传时报宽度不一致。生产留白仍至少 2 pt，诊断稿不能当生产候选。
- 同一份机器配置固定 Python、字体和引擎；配置、启动、状态与制作均由 journal.mjs 进入原统一执行器。
- 私有迁移自动携带评审注册表和发布回执；新增文字批注不再导致已发布候选重启后退回旧稿，新的制作请求仍须匹配当前批注。
- 公共包携带工作台和必要 Adobe 兼容组件，私有包不再携带另一套工作台代码。原稿、候选、批注、验收及有效证据单独哈希封装，凭据和商业字体不上传。

## 验证

完整结果以 RELEASE.json 的 validation 为准。已执行真实 PDF 六路加工、独立检查、HTTP 回传和候选可见验证；模拟断线、失败目录接续和重复请求均有回归。统一 journal.mjs produce 复用原回执，不再生成重复候选。

原机隔离工作台恢复核对：48 篇、285 条图件记录、258 个当前输出、87 张终检通过，逐图状态、批注与输出 SHA256 全部一致；浏览器已打开当前 PDF 候选及保留批注。没有修改用户终审结论。

新电脑仍须安装合法字体及所需 Office/Cairo/Adobe，并完成安装指南中的验收。Windows 无创建符号链接权限的三项测试在本机跳过，同一安全测试同时在 Linux CI 执行。历史记录中引用但原机已不存在的旧文件保留缺失清单，不假造文件；当前 48 份 Word 和 258 个输出均已入私有包。
