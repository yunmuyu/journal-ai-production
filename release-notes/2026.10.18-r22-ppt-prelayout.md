# r22：混合图与原生前置排布

本轮修复了原生换字流程中的两个问题：PDF 夹有普通图片时被整体拒绝，以及测字后仍只按指定点放字、依赖导出后返修。

- PDF 中的不透明 RGB/Gray 图片独立转灰度，矢量、文字、位置、尺寸、裁切及共享资源保留。未验证的透明/特殊颜色编码明确报错。
- 标签显式绑定所属路径；在同一份原生文档里测字、算多边形容纳、避开可见边界/箭头/其他文字/图片，允许指定的90°方向与小幅虚线矩形扩框。字号不由算法擅改。
- 真实绘制顺序和不透明覆盖参与判断，不把立体模块被前面遮住的后边当作可见障碍。复合路径有多个子路径时，不把单个子路径假设为不透明覆盖。
- 失败先报告、后停止，不保存 AI/PDF；成功后重测实际文字位置。新路线直接用实际墨迹与原生几何定界，一次保存，跳过旧的像素裁边再保存；同计划复用缓存。
- 协议与使用边界见 `references/native-label-placement.md`。必须填写标签 `layout` 和可靠的所属路径，旧计划不会凭最近的框自动猜绑定。既有验收稿不自动重做。

## 验证

65项相关 Node 测试、13项 Python 测试通过。固定入口原生实测通过居中、保字号旋转、受控扩框、混合图片保留、一次保存、缓存复用；无解样例在保存前拦截。所有保护路径只允许已声明的框变化。

本机验收稿副本回放20次：18次内部居中、2次近处外侧、0次无解；原正式文件哈希不变。该回放不是全图语义/视觉重新验收，未映射标签不计入20次。商业原稿、快照及机器路径均留在仓库外。

另确认 `tests/fit-reuse-scale.test.mjs` 的3项失败在未改的原版本同样存在；旧 `fit` 仍会走8/7/6重新生成。本轮不改该入口，新排布不调用它，不能将整库测试报告成全绿。
